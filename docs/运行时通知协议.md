# Agent Plane 运行时配置与变更通知协议 (v1)

> Runtime Configuration & Change-Notification Protocol
>
> 本规范定义**控制平面(经 Registry)如何把 Agent 及其依赖的变更通知给数据面运行时**,
> 以及运行时应如何消费。任何 Agent 运行时(LangGraph / Agents SDK / CrewAI / 自研)按本
> 规范实现即可接入,无需读 Kubernetes API,也无需了解 Agent Plane 内部实现。
>
> 参考实现:`cmd/registry/`(服务端)、`cmd/agent-runtime/` + `internal/agentloop/`(客户端)。

---

## 1. 设计原则

1. **全量快照,而非增量**:每次通知都是"当前应生效的完整配置",不是"哪几个字段变了"。
   → 运行时逻辑简单、天然幂等、丢事件也能最终收敛。
2. **单一变更令牌 `configHash`**:控制面把 Agent 及其所有传递依赖折叠成一个哈希;
   运行时只需比较哈希即可判断"要不要重载",无需理解变更细节。
3. **配置与密钥分离**:载荷只含 Secret 的**坐标**(name/key),永不含密钥值;
   密钥由运行时用自身 RBAC 读取。
4. **控制面不触发推理**:协议只回答"用什么配置",不回答"何时跑";触发由运行时入口决定。

---

## 2. 术语

| 术语 | 含义 |
|---|---|
| Registry | 控制面暴露给数据面的唯一配置端点(HTTP)。 |
| Runtime | 数据面运行时,本协议的客户端。 |
| Snapshot | 一份完整的 `AgentConfig` JSON。 |
| `configHash` | 对 Agent 已解析引用集合(kind+name+resourceVersion)求的 sha256;变更令牌。 |

---

## 3. 传输与端点

- 传输:HTTP/1.1;JSON 用 UTF-8。基址形如 `http://<registry-host>:9090`。
- 协议版本体现在路径前缀 `/v1`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/agents/{namespace}/{name}/config` | 拉取一次性快照。 |
| GET | `/v1/agents/{namespace}/{name}/watch` | 订阅变更流(SSE)。 |
| GET | `/healthz` | 存活检查,返回 `ok`。 |

### 3.1 `/config`(一次性)
- `200 OK`,`Content-Type: application/json`,body 为一个 `AgentConfig`。
- `404 Not Found`:Agent 不存在。
- `400 Bad Request`:路径不合法。

### 3.2 `/watch`(变更流,SSE)
- `200 OK`,`Content-Type: text/event-stream`。
- 事件规则:
  1. **连接建立时立即**发送一份当前快照(若 Agent 存在)。
  2. 之后**每当 Agent 发生变化**,发送一份新的完整快照。
  3. 每 ~25s 发送一行心跳注释 `: keepalive`(SSE 注释,客户端应忽略)。
- 事件格式(每个快照一帧):
  ```
  data: {"namespace":"default","name":"support-agent","configHash":"…", …}\n\n
  ```
- 断线:服务端不保证 resume 游标;客户端**重连后会收到一份全新的初始快照**(见 §6)。

## 4. 配置载荷 `AgentConfig`

```jsonc
{
  "namespace": "default",
  "name": "support-agent",
  "configHash": "bd6a92…",          // sha256 hex;Degraded 时为空串 ""
  "phase": "Ready",                  // Pending | Ready | Degraded
  "spec": { /* Agent.spec 原样透传,含各 *Ref */ },

  "model": {                         // Agent 就绪时存在
    "provider":  "custom",           // openai|anthropic|azure-openai|ollama|vllm|openrouter|custom
    "modelName": "claude-haiku-4-5-20251001",
    "endpoint":  "http://gateway/v1",
    "secretName":"llm-secret",       // ← 只给坐标
    "secretKey": "api-key"           //    密钥值不在载荷里
  },

  "tools": [                         // 已解析的工具定义(可直接调用)
    {
      "name":        "order-lookup",
      "type":        "mcp",          // http | mcp | …
      "description": "Look up a customer order…",
      "endpoint":    "http://orders-mcp.default.svc:8080",  // mcp 取自 MCPServer.status.endpoint
      "mcpToolName": "get_order_status",
      "inputSchema": { "type":"object", "properties":{ "orderId":{"type":"string"} }, "required":["orderId"] }
    }
  ],

  "skills": [ "refund-handling" ]    // markdown 指令包名(正文经 K8s 获取)
}
```

字段约定:
- 未就绪(`phase != Ready`)时,`model` 可能缺失、`configHash` 为 `""`。
- `tools[].endpoint`:`http` 型是工具自身 URL;`mcp` 型是其后端 MCPServer 的集群内端点。
- 载荷**只增不改语义**:后续版本新增字段;客户端应忽略未知字段(向前兼容)。

---

## 5. `configHash` 语义(变更令牌)

- 由控制面对 Agent 的**已解析引用集合**求哈希:每个引用是 `{kind, name, resourceVersion}`,
  顺序稳定,再 sha256。参考实现见 `internal/controller/agent_controller.go` 的 `configHash()`。
- **变**当且仅当:引用增删、或任一被引用对象(Model/Tool/Skill/…)发生变化(resourceVersion 变)。
- **不进哈希**的字段(如 Agent 的 `description`)变化不改哈希——即"不影响运行时配置"的变化不触发重载。
- Degraded → `configHash = ""`。

> 因此运行时的判定极简:`newHash != currentHash` ⇒ 需要重载;否则忽略(含心跳)。

---

## 6. 投递保证与断线重连

- **投递语义:at-least-once,允许丢中间态**。服务端广播是非阻塞的(慢消费者会丢弃中间快照),
  但因每帧都是**全量最新状态、后到覆盖先到**,运行时始终收敛到最新,不会停在旧态。
- **无 resume 游标**:重连后服务端主动下发一份初始快照,即为权威当前值 → 天然自愈,不存在
  "重连期间漏掉的事件"问题。
- 客户端**应**在连接断开后重连(带退避);**可**在不支持 SSE 时降级为周期性轮询 `/config`。

---

## 7. 运行时职责(MUST / SHOULD)

- **MUST** 把每个事件当作全量快照处理;实现必须幂等(重复/乱序快照无害)。
- **MUST** 用 `secretName`/`secretKey` 通过自身 Kubernetes RBAC 读取模型密钥;
  **禁止**期望 Registry 下发密钥值。
- **SHOULD** 比较 `configHash`,跳过无变化事件与心跳。
- **SHOULD** 在 `phase != Ready` 时保留上一份 Ready 配置继续服务(或按业务策略拒绝),
  不要用空配置覆盖。
- **SHOULD** 断线重连(指数退避);**MAY** 轮询 `/config` 作为兜底。
- **热替换 MUST 原子**:重建工具表/模型客户端后整体切换,不影响进行中的请求(读写锁/指针交换)。

最小消费循环(伪代码):
```text
open SSE /watch
on snapshot s:
    if s.configHash == current.configHash: continue        # 含 keepalive
    tools  := build_tools(s.tools)                          # 依据新配置重建
    key    := k8s_get_secret(s.model.secretName)[s.model.secretKey]
    atomically swap {current = s, tools, key}
    log "hot-reloaded", s.configHash
on disconnect: backoff, reconnect                            # 重连即拿全量快照
```

## 8. 错误与边界

| 情况 | 服务端 | 运行时应对 |
|---|---|---|
| Agent 不存在 | `/config` 返回 404;`/watch` 保持连接、暂不发快照 | 重试;保留上次配置 |
| Agent Degraded | 快照 `phase=Degraded`,`configHash=""` | 保留上一份 Ready 配置 |
| 依赖(Tool 等)后建 | 依赖就绪后 Agent 自动收敛 → 推新快照 | 收到即热载 |
| MCPServer 未就绪 | `tools[].endpoint` 可能为空 | 该工具暂不可用,勿崩溃 |
| 连接中断 | — | 重连,拿初始快照自愈 |

## 9. 版本与演进

- 当前版本 `v1`(路径前缀)。破坏性变更将升到 `/v2` 并在过渡期并行提供。
- 向前兼容规则:仅新增字段;客户端忽略未知字段。
- 规划中的演进(不属于 v1 契约):
  - `ETag` / `If-None-Match` 支持轮询短路;
  - SSE `id:` + `Last-Event-ID` 提供 resume 游标;
  - gRPC / server-streaming 传输;
  - 事件级 `kind` 提示(如 `snapshot` / `deleted`)。

## 10. 与控制面的关系(信息流)

```
Tool/Skill/Model 变更
      │  (AgentReconciler 用 .Watches + enqueueReferrers 反查引用它的 Agent)
      ▼
Agent 重新 reconcile → 重算 configHash → 写入 Agent.status
      │  (Registry 用 informer 只 watch Agent)
      ▼
Registry.onAgentChange → 组装 AgentConfig → hub.broadcast
      │  (本协议:SSE /watch 全量快照)
      ▼
Runtime 比对 configHash → 原子热替换 → 继续服务
```

即:**"有哪些变更"被控制面统一折叠为"一份新配置 + 一个新 hash",协议不传字段级 diff**——
这是本规范的核心取舍(简单、自愈、幂等)。需要字段级差异的运行时,自行对两份快照做 diff。
